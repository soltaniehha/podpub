LLMs Are Making Formal Software Verification Feasible at a Much Larger Scale (October 2026)

In this episode we unpack a new release from Anthropic's Frontier Red Team, written with the formal methods startup Theorem by Keane Lucas, Nickolai Zeldovich, Nicholas Carlini, Jason Gross and twelve colleagues and published on October 22, 2026, with a six page technical appendix. The claim: formal verification, which has historically taken years of expert effort and been reserved for things like operating system kernels and avionics, can now be done by an AI model at scale. Claude turned the existing fuzz tests of open source libraries into mathematical specifications and then wrote machine-checked proofs that the compiled programs can never crash on any input under 64 MB.

We walk through how the pipeline works on compiled RISC-V binaries using Theorem's RISC-V and Linux process semantics and the Rocq proof checker, and the headline numbers: 239 entry points proved across 123 libraries from Google's OSS-Fuzz, about 180 million lines of checked proof, and a typical proof of roughly 600,000 lines. We cover the bugs it found that fuzzing missed for years, including a decompressor underflow that needed a 20 MB input and a rediscovered libexpat CVE, the side experiments on the Linux kernel's zlib and a Verus-verified Python interpreter in Rust, the reward hacking risk of letting the model patch the code it proves, and the cost curve as newer models need about 40 percent fewer tokens. We set it against the seL4 microkernel proof, Airbus's use of the Astrée analyser, the Baldur LLM proof generator from 2023 and Anthropic's own Mythos Preview cyber assessment, and close on the limits the authors spell out: a proof is only as good as its specification and its model of the machine.
